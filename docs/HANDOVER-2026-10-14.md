## 3. PENDING - agency tenants (the next build)

Nomenclature, set by the owner: **tenant** = directly under the super admin;
**agency admin** = resells; **agency tenant** = under an agency. Use these words in code.

**The rule that makes it cheap: an agency tenant IS exactly one Signal plan.** Agency = 5
copies, Enterprise = 20, higher tiers = a bigger count. No pooled quotas, no new limits
model, no subscription per agency tenant.

Schema proposed, NOT built, nothing migrated:

- `Tenant.kind` - new enum `TenantKind`: DIRECT | AGENCY | CLIENT (rename CLIENT ->
  AGENCY_TENANT to match the nomenclature)
- `Tenant.parentTenantId` + `Tenant.parentKind`
- DB invariants, not app checks: `CHECK ((kind='CLIENT') = (parentTenantId IS NOT NULL))`,
  `UNIQUE (id, kind)`, composite FK `(parentTenantId, parentKind) -> tenant(id, kind)`
  with `CHECK (parentKind='AGENCY')`. This proves the parent is an agency and caps depth
  at two for free.
- `Subscription.clientQuantity Int @default(0)`
- No membership table: access is derived from the tree. A client login needs no new model.
- No new `Plan` enum value (avoids the ALTER TYPE-in-transaction trap).

Migration: one migration, no data movement. Every existing tenant becomes DIRECT with a
null parent.

🔴 **The real work is not the schema.** 87 sites across 45 files treat `isSuper` /
`impersonating` as "not rated against a plan". An agency entering an agency tenant must
stay METERED. Split into "platform operator" (exempt) and "acting in a workspace"
(rated). Miss one site and the Agency tier gives itself away.

**Three decisions still open:**

1. Does the agency's own workspace count toward its five? (recommendation: no)
2. Extras at $29 per agency tenant - included count vs price on top?
3. Agency's own ad-account cap (recommendation: 2, as Signal)

## 7. DONE this session - Cloudflare for SaaS

Set up on the live account, **not yet proven with a real client domain**.

| Piece | State |
|---|---|
| Fallback origin | `customhost.divineleads.guru`, proxied CNAME to `assess-production.up.railway.app`, **Active** |
| Worker | `assess360-saas-proxy`, route `*/*` on divineleads.guru |
| Worker vars | `ORIGIN_HOST`, `ZONE_HOST` (plaintext), `PROXY_SECRET` (secret, rotated) |
| Railway prod | all four `CLOUDFLARE_*` variables set, API token rolled |

🔴 **`ZONE_HOST` is load-bearing.** The route must be `*/*` because client hostnames are
unknown in advance, and that pattern also matches every proxied record in the zone -
divineleads.guru carries five other live apps (assess360, avr, cosmetic, powertools,
paymentz). The Worker passes anything at or under `ZONE_HOST` straight through to the
origin its own DNS record names. Verified: all five still return 200 with the route live.

🔴 **Workers free plan is now a single point of failure for six properties.** Over
100,000 requests in a UTC day the Worker stops (error 1027) and every proxied host in the
zone fails together. Every pass-through still counts as an invocation. Workers Paid is
$5/month for 10M requests. Recommended before the first client domain goes live.

**Remaining proof, in order:** add a domain NOT under divineleads.guru to a workspace,
point one CNAME at `customhost.divineleads.guru`, wait for the certificate, then SIGN IN
on that host. The sign-in is the only step that proves the proxy secret matches; if the
header were ignored the host would resolve to the platform instead of the tenant.

⚠️ Never register the same host as both a Railway custom domain and a Cloudflare custom
hostname. One path per host. Railway Pro and this setup are independent; upgrading breaks
nothing.
